# 事业 OS · Career System

个人事业系统：按能力分模块构建，每个模块对每个项目单独记录进度。已上线 **融资能力（中国大陆）** 和 **产品能力（想法到 PMF · 中国上线）**，其余模块（增长、团队、法务、财务）在左栏显示为「规划中」。

- 在线使用：https://claude.ai/artifact/9udghkkKWgMkY1Xg6N5HyZ（私有，进度保存在这个 Artifact 的云端数据库）

两个模块都针对仓库里两个可以规模化的项目预置了内容：**身体健康 OS**（`health-os/`）和 **破土 Groundbreak**（`groundbreak/`），也可以在页面里新增项目。

## 融资模块的 6 个视图

| 视图 | 回答什么 | 可视化 |
|---|---|---|
| 总览 | 你在哪一步、下一轮是什么、这周先做哪 3 件事 | 进度环、市场数字、对口资方排行、阶段时间线 |
| 轮次地图 | 种子到上市每轮拿多少、让多少、要有什么 | 对数刻度金额区间图、出让比例图、上市板块门槛表 |
| 找资方 | 11 类资方里先找谁、找哪几家 | 资方类型 × 项目适配度热力矩阵、机构卡片（附公开案例链接） |
| 路演 | BP 怎么写、机构内部怎么过会、会被问什么 | 过会流程图、12 页 BP 结构（按项目预填要点）、你的漏斗 |
| 交割流程 | 一轮融资从准备到打款的每一步 | 阶段甘特图、可勾选步骤清单（含国资、美元支线） |
| 我的进度 | 完成了多少、目标机构谈到哪 | 各阶段完成度、目标机构看板 |

## 产品模块的 5 个视图

| 视图 | 回答什么 | 可视化 |
|---|---|---|
| 总览 | 离 PMF 还有多远、先做哪 3 件事、下一轮融资要哪些产品数据、上线前必须处理什么 | PMF 判定环 + 4 条判定逐条通过 / 未通过 |
| 路线 | 问题验证 → 方案验证 → MVP → 中国上线 → 早期留存 → PMF 判定 → 规模化前检查，共 35 步 | 阶段完成度条、可勾选步骤（与融资模块同一套） |
| 中国上线 | 网页 / 小程序 / iOS / 安卓各要做哪些备案和合规 | 12 项要求 × 4 种形态矩阵（必须 / 视情况 / 不需要），附法规原文 |
| 指标与 PMF | 每周录入周活、新增、付费、留存队列和调研，自动判定 | 留存曲线（对照品类基准）、周活与新增趋势、「非常失望」比例、NPS |
| 产品体检 | 两个项目的代码现在有什么、缺什么 | 11 个维度 × 2 个项目状态矩阵，每格附 `文件:行号`，缺口链到对应步骤 |

PMF 判定的 4 条：① 数据够（≥ 3 个有第 4 周数据的队列，或调研 ≥ 40 份）；② Sean Ellis「非常失望」≥ 40%；③ 留存曲线走平（第 12 周 / 第 4 周 ≥ 0.8，本系统规则）；④ 第 24 周留存达到所选品类的「好」线（Lenny Rachitsky 从业者调查，美国口径）。NPS 只展示，不参与判定。品类基准按项目赛道给默认值（健康 → 消费订阅，平台 → 消费交易，SaaS → 中小企业 SaaS 等，见 `DEFAULT_CAT`），可在「指标与 PMF」页改。

与融资模块联动：融资总览显示「产品准备度」（PMF 判定、第 4 周留存、最近周活、路线进度）；路演页 BP「数据与进展」引用录入的最新数据；产品总览把融资下一轮的门槛翻成产品目标。

深链接：`#pitch` 打开融资模块的某个视图，`#product/metrics` 打开产品模块的某个视图。

## 构建

```bash
node build.mjs           # 校验并生成 index.html
DRAFT=1 node build.mjs   # 草稿：把校验问题打印出来但仍然生成页面
```

校验项：每条来源都有 https 链接和日期；正文里 `[[key]]` 形式的引用和每个 `src` 都能在 `SRC` 里找到；步骤 id 跨模块唯一且属于已知阶段，产品步骤以 `pd-` 开头；每家机构都有公开案例和链接；每个赛道对每类资方都有适配度和理由；上线矩阵每格取值合法、每行有来源；融资门槛覆盖每一轮；体检证据必须是 `路径` 或 `路径:行号`，文件真实存在且有那一行，每个缺口都对应一个步骤；PMF 判定规则、融资门槛引用的规则和指标字段、步骤的赛道限定和项目提示、每个赛道的默认留存基准都要对得上已知取值。任何一项不过都会报错并停止生成。

`index.html` 不含 `<html>/<head>/<body>`，发布为 claude.ai Artifact 时由平台补齐。发布时声明 `db` 和 `user` 能力。

## 数据结构（云端）

```
projects/{pid}                     新增的项目：name, sector, stage, note, order
projects/{pid}/steps/{stepId}      步骤进度：done, note, at
projects/{pid}/targets/{instId}    目标机构：status(target|contact|meet1|meet2|ts|dd|closed|pass), note, at
projects/{pid}/metrics/{YYYY-Www}  周指标：wau, newUsers, payers, revenue, note, at
projects/{pid}/cohorts/{YYYY-Www}  留存队列（按注册周）：size, w1, w4, w12, w24（第 N 周仍在用的人数）, at
projects/{pid}/surveys/{id}        调研：pmf-{日期} → type:'pmf', n, very, date；nps-{日期} → type:'nps', promoters, passives, detractors, date
projects/{pid}/meta/product        产品设置：category（留存基准品类）
```

内置项目（`health-os`、`groundbreak`）的定义在 `src/projects.js` 里，不写入数据库；数据库只存你的进度、备注、目标机构和新增项目。云端不可用时，同样的数据存在浏览器 `localStorage`（键前缀 `cos.`），只在这台设备上可见。

## 口径

- 数字和法规条文都附来源和日期，截至 2026 年 10 月。
- 资方适配度（0–5）是本系统对种子 / 天使轮的判断，理由写在每一格旁边。
- 留存基准来自美国从业者调查，没有找到中国同口径的公开数据；「走平」的 0.8 阈值是本系统规则。
- 安卓商店的软著要求没有找到商店官方原文，标为「视情况」，以各商店审核指南为准。
- 机构只列公开可查的投资案例，不代表它现在一定在投，也不含任何联系人信息。
- 内容不构成投资或法律意见，上线和签约前请律师复核。
